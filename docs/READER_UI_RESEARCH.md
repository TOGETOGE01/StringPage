# 弦页阅读界面研究

建议把下一轮改版集中在阅读页。打开乐谱后，页头说明正在看哪首歌、哪个声部，底栏显示播放和练习状态，谱面承担乐谱定位与循环范围反馈。手机用一张随用随开的练习面板，平板可以把这张面板停靠到谱旁。

## 现有界面审计

在暖陶主题下，用同一份 16 小节 GP 测试谱检查了手机竖屏（约 393 × 873 dp）和接近小米 Pad 7 Ultra 比例的平板横屏（1600 × 1068 dp）。下列占比以模拟器截图中的谱面视口为准，包含可滚动的留白，随曲目和谱面设置变化。真机比例、触控和缩放手感仍需实测。

| 观察 | 使用中的影响 | 改版要求 |
| --- | --- | --- |
| 手机上第一行谱之前有品牌栏、曲名区和工具行。谱面约占截图高度的 59%。 | 首次看谱前需要扫过三层信息，视谱面积还可以增加。 | 合并品牌栏和曲名区。声部、音源留在同一行，低频信息从详细信息打开。用同一首谱、同一缩放复测高度。 |
| 平板两侧分别固定为 214 dp 和 244 dp，谱面视口约占屏宽的 69%。同一曲名在应用标题和谱面页首各出现一次。 | 跟练期间曲库仍占用宽度，大屏也只有三分之二左右的横向空间用于谱。 | 曲库和练习区可独立收起。应用阅读视图只显示一处重复的曲名，打印和导出保留乐谱信息。 |
| 播放速度在底部显示为 `1.0×`，右栏又显示 `100%`，谱面工具还显示一个 `85%`。节拍器藏在混音与练习设置内。 | 中断练习调整参数时，需要先分辨同类数字，再找开关。 | 统一用 `速度 60%`、`节拍 72 BPM` 和 `缩放 85%` 表达三种量。开关、显示值和状态在各音源使用同一规则。 |
| 底部常驻状态句，右侧又常驻音频详情。左栏近期项目逐行显示删除图标。 | 浏览和管理操作持续占据视线。进入练习后，重要反馈是当前声部、播放位置与选段。 | 同步点数量、文件名和音源诊断归到音频详情。近期移除功能放到项目菜单或管理状态，并保留键盘与读屏入口。 |

现有实现将谱面工具、底栏、边栏和平板断点集中在 `MainActivity`，将节拍器和混音选项放在 `PlaybackControls`。推进时可在现有 Android Views 中复用控件与状态，先验证设计，再决定结构拆分的幅度。 [布局实现](../app/src/main/java/com/stringpage/app/MainActivity.kt) · [练习设置实现](../app/src/main/java/com/stringpage/app/PlaybackControls.kt)

## 推荐布局

### 手机竖屏和窄窗口

```text
‹ 曲库           曲名                 ⋯
当前声部 ▾             音源 ▾     谱面 ▾
┌───────────────────────────────────┐
│                                   │
│              可滚动谱面            │
│          A  ├────────┤ B          │
│                                   │
└───────────────────────────────────┘
小节 12 / 96    ──────────   0:36 / 4:13
播放      速度 60%    循环 12–16    节拍 72
```

- 底栏维持播放、速度、循环和节拍器四个触点。节拍器单击切换，开启时显示 `72 BPM`，关闭时显示 `节拍器关`。底栏空间不足时先压缩文字，触控区域维持 48 dp。完整设置在练习面板显式提供，长按只作快捷操作。
- 点击速度或循环打开同一张底部面板的对应区域。速度提供 10%–100% 滑条和数字输入，循环提供起点与终点，节拍器提供跟随乐谱、自定义 BPM、细分和音量。常用值一次可改，面板打开后还能看见当前小节。
- 循环有明确的「选起点」「选终点」状态，完成后在谱面上直接显示选区，底栏显示 `循环 12–16`。正常读谱时点谱仍是跳转。编辑模式优先使用点选音符的交互。数字输入保留给熟悉小节编号的用户。
- 顶部主标题只保留一行曲名，副行承载声部和音源。音源变更放在已有声源选择器，字号、谱表、全屏放在「谱面」。空白页可用大一点的导入按钮，进入已打开的乐谱后把导入收回曲库入口。

### 小米 Pad 7 Ultra 和宽窗口

```text
曲库开关     曲名 · 声部                  音源   谱面   更多
┌───────────┬────────────────────────┬───────────┐
│ 曲库       │                        │ 练习   收起 │
│ 最近打开   │         乐谱           │ 速度 60%   │
│            │                        │ 循环 12–16 │
│ 可独立收起 │                        │ 节拍 72 BPM│
│            │                        │ 音量与混音 │
└───────────┴────────────────────────┴───────────┘
播放            进度轨与循环位置                 小节与时间
```

- 三栏便于找谱。选好曲目后，可只收曲库，保持右侧练习区。演奏期间也可收起两侧查看整页。面板开关放在固定位置，记住本机选择。右侧优先显示速度、循环和节拍，谱表和缩放从页头进入，详细参数可展开。
- 手机横屏、平板竖屏和分屏按实际窗口判断。只有剩余空间够读谱时才并排停靠。建议先试用 720 dp 谱面可用宽度作为双栏退让线，具体数值以验收谱为准。窄窗把同一面板改为底部或边缘浮层，保持现有声部与播放状态。
- 跟随播放时保留下一行的可见空间，测试当行最后两个小节和跨行回绕。一旦用户主动滚动，可用「回到播放位置」返回，避免跟随刷新干扰主动查谱。

## 视觉规范与取舍

- 使用暖陶的纸面、深墨和陶红作为默认视觉。深色主导航在宽屏用于曲库边栏，手机已打开的谱页让主题色集中在播放和明确的选中状态。四套主题共享布局和状态写法。
- 曲名保留现有的衬线识别度，控制区统一无衬线。手机标题从 20–22 sp 起试，平板从 24–28 sp 起试，辅助信息从 13 sp 起试。数字使用等宽字形，速度、时间和 BPM 更新时位置稳定。间距采用 4、8、12、16、24 dp，常规控件与分组用两个圆角级别即可。
- 谱面强调分三层。当前拍用一条清晰的播放线，循环用淡底和 `A`、`B` 标记，编辑选中音符用独立轮廓。即使在夜墨或灰度显示中，也能区分三种状态。状态文案只在有意义时显示，播放、循环、节拍开关同时给读屏提供名称与状态。
- 用现有 `ReaderTheme` 的 sRGB 颜色计算对比度，四套主题的辅助文字对面板为 **5.68–7.32:1**，主按钮文字对强调色为 **6.57–9.99:1**，但选中底色对普通控件底色仅 **1.07–1.16:1**。改造的重点是增加选中状态的勾标、短标签或轮廓，浅底只起辅助作用。计算仅覆盖代码里的纯色对，叠加在真实谱面上的播放线和标记要单独检查。 [主题调色板](../app/src/main/java/com/stringpage/app/ReaderTheme.kt) · [W3C 非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

## 小步开发和验收

| 顺序 | 交付内容 | 验收方式 |
| --- | --- | --- |
| 第一版 | 共用练习面板和底栏状态，接入现有节拍器、速度和循环设置。 | 播放中一步开关节拍器，底栏实时更新 BPM；设置 60% 预置速度最多两次点击。打开、关闭面板期间，播放位置、当前声部和循环不变。 |
| 第二版 | 手机紧凑页头和平板独立边栏开关。 | 用同一测试谱、同一缩放，手机谱面视口从约 59% 提升到至少 65%；平板关闭曲库、保留练习区时，谱面宽度从约 69% 提升至至少 82%。检查长曲名、长声部名、字体放大和横竖屏切换。 |
| 第三版 | 谱面 A/B 选段标记与跟随播放优化。 | 用短练习曲、密集吉他六线谱和带歌词的 GP 文件，验证选段、回绕、跨行预读和触屏编辑。原来的小节数字输入仍可用。 |

第一版可用一条完整的练习脚本比较改前和改后。打开乐谱，切到目标声部，将速度设为 60%，打开节拍器并设八分音符，再循环 12–16 小节。记录点击次数、谱面被遮挡时间和是否误触。复测四套主题、小屏竖屏、小屏横屏、Pad 横屏和分屏，并用 TalkBack 检查切换控件是否读出了状态。最终真机验收加入音源切换和横竖屏过程，检查游标、速度和节拍器能否接续。

## 一手资料与设计启示

| 研究对象 | 第一手资料中的做法 | 对弦页的启示 |
| --- | --- | --- |
| Android 大屏布局 | Android 按应用窗口宽度和高度划分尺寸。宽窗口可同时显示内容与辅助面板，窗口收窄时保留内容和导航状态。手机横屏的高度也会限制可用布局。 [窗口尺寸级别](https://developer.android.com/develop/ui/views/layout/use-window-size-classes) · [规范布局](https://developer.android.com/develop/adaptive-apps/guides/canonical-layouts) | 把谱面当作持续存在的主视图，曲库与练习控件随窗口重排。用谱面实际剩余空间决定显示多少辅助控件，同时保留播放位置、声部和循环设置。 |
| forScore 阅读界面 | forScore 默认收起主要控件，提供不同的乐谱适配视图，也允许调出操作栏。 [forScore 阅读指南](https://forscore.co/documentation/basics/) | 常驻控件可以减量，现有「全屏看谱」是自然入口。弦页的谱面点击已有播放定位语义，宜用明确的按钮进入和退出全屏。 |
| Soundslice 循环练习 | 在触屏设备，Soundslice 从当前小节建立循环，起止点可在谱面上调整，播放时收起选择菜单。 [Soundslice 循环指南](https://www.soundslice.com/help/en/player/basic/4/looping/) | 把当前小节作为选段起点，让起点、终点和播放范围直接显示在谱面上。数字输入可以作为精确定位入口，练习者可随时核对正在循环哪些小节。 |
| Soundslice 谱面和跟随 | Soundslice 区分重排与整页缩放，可选滚动、分页、横向版式，也能调整播放光标触发滚动的时机。研究中观察到视奏者的视线会先于演奏位置。 [Soundslice 缩放](https://www.soundslice.com/help/en/player/basic/101/resizing-notation/) · [光标滚动选项](https://www.soundslice.com/help/en/player/advanced/116/playhead-scrolling-options/) · [小提琴视奏实证研究](https://pubmed.ncbi.nlm.nih.gov/19205680/) | 把谱面字号和每行容纳的小节数一起验收，滚动保留下一段的阅读空间。视奏实验只支持预读需求的方向，具体滚动阈值应从弦页的手机与平板试用中决定。 |
| 节拍器状态 | forScore 将 BPM 与拍号作为直接可调的控件。Soundslice 的更新记录说明，关闭节拍器时以前会连同音量设置一起隐藏，影响设置可发现性。 [forScore 节拍器](https://forscore.co/documentation/metronome/) · [Soundslice 更新记录](https://www.soundslice.com/blog/255/player-updates-september-7/) | 在同一个入口显示开关状态和 BPM，设置面板保留跟谱／自定义及细分节奏。涉及 BPM、播放速度、谱面缩放的数值，应通过单位和文本明确区分。 |
| Guitar Pro 移动版 | 官方 Android 手册把谱表模式、谱面大小、节拍器和预备拍列为独立设置，谱面大小随方向和内容调整。 [Guitar Pro Android 设置手册](https://support.guitar-pro.com/hc/en-us/articles/202325332-GP-Mobile-Android-Settings-menu) | 「谱面」承担显示与缩放，「练习」承担循环与节拍，「音频」承担音源与混音。右侧辅助面板和手机入口可以复用这一操作归属。 |

Android Views 建议交互区域至少 48 × 48 dp，小图标可通过额外的触控面积达到这一尺寸。为纯图标控件设置能读出的动作和状态。循环有效、节拍器开启、声部选中等状态应有文字、标记或形状。建议将小字号工具文字的对比度目标定为 4.5:1，交互边界和有效状态的图形目标定为 3:1，作为弦页自有视觉验收值。 [Android Views 无障碍指南](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views) · [WCAG 文字对比度](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html) · [WCAG 非文字对比度](https://www.w3.org/WAI/WCAG21/Understanding/non-text-contrast.html) · [WCAG 颜色的使用](https://www.w3.org/WAI/WCAG21/Understanding/use-of-color.html)
